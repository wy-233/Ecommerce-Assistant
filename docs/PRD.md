## 2. 背景与目标

### 2.1 背景

跨境电商卖家日常客服中，售后政策、订单、库存、物流四类问题高频且重复。参考仓库 agent-service-toolkit 提供了基于 LangGraph、FastAPI、Streamlit 的通用 Agent 服务骨架，本产品在其结构上落地一个面向电商场景的助手，先跑通「意图识别 → 知识库或业务工具」的最小演示闭环。

### 2.2 目标

- 第一期交付一个可本地运行、可演示、可测试的 AI 助手 MVP，覆盖售后知识问答、订单查询、库存查询、物流查询四类场景。
- 验证意图识别与路由链路：售后 / 商品问题走 RAG 知识库，订单、库存、物流问题分别调用独立工具。
- 为后续接入真实 ERP、扩展退款改地址等能力保留清晰的结构边界。

### 2.3 成功标准

第一阶段按本 PRD 第 9 节验收清单逐项通过，即视为完成；验收清单源自设计文档，共 11 项，覆盖接口、工具、RAG、会话隔离、测试与文档。

## 3. 用户与核心场景

### 3.1 目标用户

跨境电商卖家及其客服人员。第一阶段为本地演示与试用形态，用户通过 Web 前端提问；真实运营用户的分群与权限需求未纳入本期，待第二阶段明确。

### 3.2 核心场景

| 场景 | 示例问题 | 期望结果 |
| --- | --- | --- |
| 售后政策咨询 | 退货需要满足什么条件？ | 返回知识库回答，并附来源引用 |
| 订单查询 | 订单 1001 现在到哪里了？ | 调用订单工具，返回订单状态 |
| 库存查询 | 商品 SKU-001 还有库存吗？ | 调用库存工具，返回库存数量 |
| 物流查询 | 订单 1001 使用了什么物流？ | 调用物流工具，返回物流信息 |
| 无法识别 | 与业务无关的普通问题 | 兜底回复，不调用工具，不崩溃 |

## 4. 范围界定

### 4.1 本期实现

- 意图识别与四类路由：售后 / 商品 → RAG 知识库；订单、库存、物流 → 对应业务工具。路由结果以结构化字段 `route` 返回给前端，不由前端自行判断。
- 售后知识库问答（RAG），回答包含来源引用，来源以结构化字段 `sources` 返回。
- 订单、库存、物流三个查询工具，基于本地演示数据。
- 会话隔离：以 thread_id 区分对话状态。
- 核心 Agent 接口：GET /info、POST /ecommerce-assistant/invoke、POST /ecommerce-assistant/stream（SSE）；并提供模型、Dashboard、订单、库存、物流只读查询接口。
- 独立 Web 前端（参照实现 `design/index.html`）、pytest 核心测试、Docker Compose 容器化。

### 4.2 暂不实现

设计文档明确后置以下内容，本期不得以任何形式重新进入主流程或验收：真实 ERP 对接；退款和改地址；多 Agent；用户登录；复杂前端；模型训练。

其中「复杂前端」指多页面路由、全局状态管理、组件库与主题系统等工程化内容。本期的 Web 前端为单页演示形态，不含上述内容，与 v0.1 中「Streamlit 演示前端」的定位一致，仅实现载体不同。

### 4.3 边界说明

- 三个业务工具均基于本地演示数据模拟，不连接任何真实业务系统。
- 知识库正文存储在 SQLite `knowledge_articles` 表中，初始内容来源于退货与物流政策文档；对外发布前仍需业务方审核政策内容。
- 售后生成式回答与通用问答依赖大模型服务（配置项 OPENAI_API_KEY）；订单、库存、物流查询由确定性 SQLite 查询完成，不依赖模型生成业务数据。

## 5. 产品方案总览

### 5.1 主流程

用户问题经意图识别后路由到四类处理链之一，无法识别时走兜底回复；所有链路统一输出 ChatMessage 供前端展示。路由关系与异常恢复见下图。

> 落盘注记：原文档此处含路由图，图片未随文本一并提供。

### 5.2 技术栈与架构要点

- 语言与依赖：Python >=3.12,<3.15（已核实参考仓库 pyproject.toml），依赖管理使用 uv。
- 服务层：FastAPI 提供 REST 接口与 SSE 流式响应；Pydantic 定义请求、响应与数据模型。
- 编排层：LangGraph 构建 ecommerce_graph，负责意图识别与工具路由。
- 工具层：`src/ecommerce_assistant/tools/database.py` 提供统一业务查询函数，订单、库存、物流 Agent 工具与 API 复用该层。
- 检索层：SQLite `knowledge_articles` 表承载知识库检索，`src/ecommerce_assistant/rag/retriever.py` 读取正文与来源。
- 前端与客户端：独立 Web 前端（单页演示形态，参照实现 `design/index.html`，规格见 `design/FRONTEND-SPEC.md`）；HTTPX 实现 AgentClient 调用后端。
- 部署：Docker Compose 一键启动。

### 5.3 最小调用链

当前有两条前端调用链：独立 Web 前端直接调用 `POST /ecommerce-assistant/invoke`；Streamlit 通过 `src/ecommerce_assistant/client/client.py` 的 `AgentClient` 调用同一接口。后端统一进入 `src/ecommerce_assistant/api/service.py` → `get_agent("ecommerce-assistant")` → `_handle_input()` → `ecommerce_graph.ainvoke()` → RAG 或业务 Tool → ChatMessage。

## 6. 功能需求

### 6.1 FR-1 意图识别与路由

| 环节 | 说明 |
| --- | --- |
| 前置与触发 | 用户在任意会话（thread_id）提交一条消息。 |
| 系统行为 | 识别问题类型：售后 / 商品、订单、库存、物流；命中后路由到对应处理链。识别实现方式（LLM 函数调用或规则分类）未在设计文档中指定，由研发确定，需保证四个演示问题稳定命中。 |
| 用户可见结果 | 四类演示问题分别进入对应链路；无法识别时返回兜底回复。 |
| 异常与恢复 | 意图不明确或与业务无关：不调用任何工具，返回明确提示（如暂不支持该问题、可咨询售后 / 订单 / 库存 / 物流事项），服务不崩溃。 |
| 验收 | 设计文档演示问题逐条测试，路由结果正确；普通问题不崩溃（验收项 4、5、6、10）。 |

### 6.2 FR-2 RAG 售后知识库问答

| 环节 | 说明 |
| --- | --- |
| 前置与触发 | data/return_policy.md、data/shipping_policy.md 已完成导入（ingest）；用户提出售后 / 商品类问题。 |
| 系统行为 | 检索相关文档片段，基于检索结果生成回答，并把来源以结构化字段 `sources` 随 ChatMessage 返回（见 6.7.1）。正文中可保留来源描述，但前端渲染以 `sources` 为准。 |
| 用户可见结果 | 如「退货需要满足什么条件？」返回政策要点并附来源；未命中时提示知识库未覆盖该内容，不编造政策。 |
| 异常与恢复 | 文档未导入或检索无结果：返回明确提示，不中断会话。 |
| 验收 | 售后文档可被检索（验收项 7）；RAG 回答的 `sources` 字段非空，且前端据此渲染来源块（验收项 8）。 |

### 6.3 FR-3 订单查询工具

| 环节 | 说明 |
| --- | --- |
| 前置与触发 | 意图识别为订单问题，如「订单 1001 现在到哪里了？」。 |
| 系统行为 | 按订单号查询本地演示数据，返回订单状态；工具可脱离 Agent 独立调用（含单测）。 |
| 用户可见结果 | 返回订单状态、商品和包裹摘要；按需可查询订单商品、包裹和独立状态结果。 |
| 异常与恢复 | 订单号不存在：返回明确错误信息（如未找到该订单），不猜测、不崩溃。 |
| 验收 | 验收项 4（订单工具可独立调用）、未找到订单返回明确错误（设计文档验证结果第 5 条）。 |

### 6.4 FR-4 库存查询工具

| 环节 | 说明 |
| --- | --- |
| 前置与触发 | 意图识别为库存问题，如「商品 SKU-001 还有库存吗？」。 |
| 系统行为 | 支持按 SKU 精确查询、按商品名搜索和按仓库筛选；工具可脱离 Agent 独立调用（含单测）。 |
| 用户可见结果 | 返回 `on_hand`、`reserved`、`available`、`safety_stock`，并按统一规则返回库存状态。 |
| 异常与恢复 | SKU 不存在：返回明确错误信息，不崩溃。 |
| 验收 | 验收项 5（库存工具可独立调用）。 |

### 6.5 FR-5 物流查询工具

| 环节 | 说明 |
| --- | --- |
| 前置与触发 | 意图识别为物流问题，如「订单 1001 使用了什么物流？」。 |
| 系统行为 | 支持按 `shipment_id`、`order_id` 或 `tracking_number` 查询，返回当前状态及按时间升序排列的轨迹；按订单查询时返回全部包裹。工具可脱离 Agent 独立调用（含单测）。 |
| 用户可见结果 | 返回匹配包裹的承运商、运单号、当前状态和轨迹。 |
| 异常与恢复 | 参数错误、数据不存在、订单无物流记录和数据库错误返回可区分的结构化结果，不猜测、不崩溃。 |
| 验收 | 验收项 6（物流工具可独立调用）。 |

### 6.6 FR-6 会话隔离

| 环节 | 说明 |
| --- | --- |
| 前置与触发 | 调用方在请求中携带 thread_id（如 demo-thread-001）与 user_id（如 demo-user-001）。 |
| 系统行为 | 以 thread_id 为维度保存与恢复对话状态。 |
| 用户可见结果 | 不同 thread_id 之间的对话互不干扰。 |
| 异常与恢复 | thread_id 缺失或为空：返回参数错误提示（口径待研发与产品确认）。 |
| 验收 | 验收项 9（不同 thread_id 的对话状态互相隔离）。 |

### 6.7 FR-7 服务接口

| 环节 | 说明 |
| --- | --- |
| GET /info | 返回服务信息，包含可用 Agent（ecommerce-assistant）与模型信息。 |
| POST /ecommerce-assistant/invoke | 入参：message、thread_id、user_id；响应为 ChatMessage，字段定义见 6.7.1。示例：message「订单 1001 现在到哪里了？」返回 content「订单 1001 当前正在运输中」，route 为 order，tool_calls 含 order_lookup(order_id="1001")。 |
| POST /ecommerce-assistant/stream | SSE 流式响应，事件类型见 6.7.2，以 data: [DONE] 结束。 |
| 异常与恢复 | 入参缺失、服务内部错误返回标准错误响应，不导致进程退出。 |
| 验收 | 验收项 1（/info 返回 ecommerce-assistant）、2（/invoke 返回 ChatMessage）、3（/stream 返回 SSE）。 |

#### 6.7.1 ChatMessage 字段定义

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| type | string | 是 | 消息类型，如 ai、human、tool。 |
| content | string | 是 | 回答正文，供前端按段落渲染。 |
| tool_calls | array | 是 | 本次回答调用的工具列表，每项含 name、args，可选 result；无调用时为空数组，不得为 null。 |
| run_id | string | 是 | 本次运行标识。 |
| route | string | 是 | 意图路由结果，取值 after、order、stock、ship、unknown 之一。前端据此决定分拣带展示与配色，不得自行推断。 |
| sources | array | 是 | RAG 来源列表，每项含 doc（文档路径）、snippet（命中片段），可选 placeholder（是否占位文本）；无来源时为空数组，不得为 null。 |

#### 6.7.2 SSE 事件类型

| 事件 | 载荷字段 | 说明 |
| --- | --- | --- |
| start | run_id | 流开始，前端据此创建待完成状态的回执。 |
| route | route | 意图判定结果，先于正文到达，前端据此播放投递动效。 |
| tool_call | name、args | 每次工具调用发一条。 |
| token | content | 正文增量。 |
| sources | sources | RAG 来源，结构同 ChatMessage.sources。 |
| error | message | 出错说明；流仍以 [DONE] 正常结束。 |

除 token 与 [DONE] 外，其余事件均为可选：非 RAG 链路不发 sources，无工具调用不发 tool_call。前端在事件缺失时须正常降级，不得报错。

### 6.8 FR-8 Web 前端

| 环节 | 说明 |
| --- | --- |
| 前置与触发 | 后端已启动；用户在浏览器打开前端地址。 |
| 系统行为 | 独立 Web 前端直接调用后端 `/invoke`，展示回答；按 ChatMessage 的 route 与 sources 渲染路由结果与来源引用。界面规格见 `design/FRONTEND-SPEC.md`。 |
| 用户可见结果 | 可输入问题并查看回答，演示链路完整可用；命中知识库的回答显示来源块，未识别的问题显示兜底提示。 |
| 异常与恢复 | 后端未启动时给出可理解的连接失败提示，说明排查方向，不静默失败。 |
| 验收 | README 指引下从零启动前后端并完成演示（验收项 11）。 |

### 6.9 FR-9 配置与密钥安全

| 环节 | 说明 |
| --- | --- |

## 7. 非功能需求

### 7.1 可用性与健壮性

任意输入（包括无关问题、空消息、超长文本）不得导致服务崩溃；无法回答时返回明确提示（验收项 10）。性能在本阶段以「演示可用、响应可接受」为定性门槛，不设量化 SLA，待第二阶段按真实用量定义。

### 7.2 可维护性

Python 代码统一位于 `src/ecommerce_assistant/` 包下，按 `agents`、`api`、`client`、`db`、`rag`、`tools`、`schema`、`workbench` 分层；独立 Web 前端位于 `frontend/`，设计参照与规格位于 `design/`；依赖通过 `uv sync` 管理并提交锁文件。

### 7.3 可移植性

通过 Docker Compose 提供一键启动；README 保证新环境可从零运行。

### 7.4 安全性

API Key 只存放于 .env，不提交 Git；示例密钥仅用于测试环境（参考仓库 pytest 亦以假密钥占位）。本期无用户登录与鉴权，接口仅限本地演示。

### 7.5 可测试性

pytest 至少覆盖核心工具（订单、库存、物流）与接口（/info、/invoke、/stream）；测试不得依赖真实外部服务。

## 8. 数据与演示数据

### 8.1 知识库文档

`data/return_policy.md`（退货政策）和 `data/shipping_policy.md`（物流政策）是初始内容来源；运行时检索读取 SQLite `knowledge_articles` 表，不再读取硬编码字典。当前政策文本用于演示，对外发布前须经业务方审核。

### 8.2 演示数据

`data/demo/*.csv` 是演示业务数据的权威源，当前基线包含 20 个订单、35 条订单明细、10 个 SKU、15 个包裹和 30 条物流轨迹。库存状态按 `available` 与 `safety_stock` 规则计算，状态枚举见 `src/ecommerce_assistant/schema/statuses.py`。

### 8.3 会话与用户标识

示例值 demo-thread-001、demo-user-001；thread_id 承担会话隔离（FR-6），user_id 本期仅透传记录，不做权限控制。

## 9. 验收标准

以下 11 项源自设计文档第 10 节，逐项通过即完成第一阶段。

| 序号 | 验收项 | 验证方式 |
| --- | --- | --- |
| 1 | /info 返回 ecommerce-assistant | curl 或接口文档调用 |
| 2 | /invoke 返回 ChatMessage | 请求返回 type、content、run_id、route、sources、tool_calls 六个字段，且 route 为合法枚举值 |
| 3 | /stream 返回 SSE | 收到 start、route 事件与 token 增量、[DONE] 结束标记 |
| 4 | 订单工具可独立调用 | pytest 单测 |
| 5 | 库存工具可独立调用 | pytest 单测 |
| 6 | 物流工具可独立调用 | pytest 单测 |
| 7 | 售后文档可被检索 | 检索链路返回文档片段 |
| 8 | RAG 回答包含来源 | 响应的 sources 字段非空（含 doc 与 snippet），且前端渲染出可展开的来源块 |
| 9 | 不同 thread_id 的对话状态互相隔离 | 双会话并发验证 |
| 10 | pytest 至少通过核心工具和接口测试；普通问题不崩溃 | 运行 pytest；无关问题压测 |
| 11 | README 能让别人从零启动项目 | 新环境按 README 完整复现，含后端与 Web 前端的启动步骤 |

## 10. 里程碑与实现顺序

按设计文档第 11 节固定实现顺序，每阶段以可运行、可验证为进入下一阶段的条件。

1. 业务工具：订单、库存、物流三个工具先行实现并通过独立测试（对应验收项 4、5、6）。
2. RAG：知识库导入与检索，回答带来源（对应验收项 7、8）。
3. LangGraph Agent：意图识别与路由，串联 RAG 与工具。
4. FastAPI：/info、/invoke、/stream 三个接口（对应验收项 1、2、3）。
5. AgentClient：HTTPX 客户端封装。
6. Web 前端：演示链路打通。
7. 测试与 Docker：补齐 pytest 与 Docker Compose（对应验收项 10、11）。

## 11. 风险与依赖
